# `[Agentic Eng Assignment] Tool server and agent - Sri Krishna Mishra`

## Summary

This repository adds a Bodhan MCP stdio server and a bounded task agent for
Indic transcription, translation, speech synthesis, OCR, media inspection, and
PDF rendering. The agent plans through an OpenAI-compatible LLM, executes
Bodhan tools, verifies generated output, and writes replayable traces.

## How to run

```powershell
py -3.11 -m venv .venv
.\\.venv\\Scripts\\Activate.ps1
.\\.venv\\Scripts\\python.exe -m pip install -e ".[dev]"
Copy-Item .env.example .env

.\\.venv\\Scripts\\python.exe -m bodhan_mcp

.\\.venv\\Scripts\\python.exe -m bodhan_agent `
  --task "Transcribe this Hindi voice note and give me English subtitles" `
  --files demo/inputs/voice-note.wav `
  --out ./out/demo-hindi-srt `
  --max-cost-inr 2
```

`ffmpeg` must be on `PATH`; Poppler is required for PDF rendering.

## Architecture

See [architecture](docs/architecture.md).

The MCP server registers typed tools and translates them to Bodhan API calls.
The task agent owns LLM planning, file summaries, budgets, verification, trace
writing, and artifacts. Media remains on local paths.

## Agent flow

See [agent flow](docs/agent_flow.md).

The loop preflights inputs, reserves bounded steps/cost/time, executes tool
calls, verifies translations or audio, retries failed verification once, and
stops honestly at missing inputs or exhausted budgets.

## Tool design

- Model-granular tools keep API schemas clear while server code owns chunking,
  format conversion, retries, caching, and cost accounting.
- `inspect_media` handles local media metadata without inline base64.
- `transcribe` handles 16 kHz mono conversion and bounded transcription windows.
- `translate` preserves source text and verifies numeric and table shape.
- `synthesize` handles sentence/chunk splitting and local WAV assembly.
- `ocr` and `render_pdf_pages` process image/PDF inputs page by page.
- `detect_language`, `list_voices`, and `list_supported_languages` are helpers
  for planning and validation.

## Where the LLM is used, and why

The LLM reads a natural-language task and file-path/metadata summaries, chooses
tool calls, makes English explanations or assumptions, and decides whether to
continue. Indian-language text is not written or rewritten by the LLM; speech,
translation, transcription, OCR, and generated audio come from Bodhan tools.
OCR/transcript text is treated as untrusted data.

## Bodhan models used

- Indic-Transcribe for speech-to-text
- Indic-Translate for translation
- Indic-Speak for speech synthesis
- Indic-OCR is wired for OCR, but the demonstrated OCR provider call failed
  with HTTP 500 and is not claimed as working

microphone recording.

## Trade-offs and known limitations

- OCR provider integration is not currently successful.
- Missing media and unsupported tasks stop honestly.
- Hidden-task success, native-speaker quality review, and all rubric demo
  coverage are not claimed.
- Streaming HTTP, resumption, and a web UI are not implemented.
